# 学習率の計画（研究メモ、ROADMAP 研究・inbox #21-3c の副産物）

2026-10-08。出典（本文で確認）: Hägele, Bakouch, Kosson, Ben Allal, Von Werra, Jaggi, "Scaling Laws and Compute-Optimal Training Beyond Fixed Training Durations"（arXiv 2405.18392）。定数の学習率で学び、最後の 20% だけ 0 へ下げる（cooldown。式(1)、形は線形か 1−sqrt）と cosine と同じくらい良い。終わりの歩数を前もって決めなくてよい。定数の間の重みを平均する（SWA）だけでも、cooldown との差はかなり縮まる（§4.1）。

## 何が効くのか
brain-merge.md の副産物（Adam 0.02、675B で const 2.19 → linear 1.43）は「学習率を下げたから」か「下げ方の形」かが分からなかった。常駐の赤子は 3e-3 の定数で、終わりが無い（DMN が 2 周ずつ回り続ける）ので、cosine のように全体の長さを前提にした計画は入らない。

## 測った（probe、`tests/llm/lr_sched_probe.c`、R=16 周、TEACHER_FIXTURE 4155B・seqlen 32・後ろ 1/4 が held、種3つ。cert ではない）
held の最後（種 0/1/2）:
- const 3e-3（今）: 2.560 / 2.675 / 2.568
- linear 3e-3→0: 2.519 / 2.630 / 2.571
- cosine: 2.497 / 2.577 / 2.548（3つとも const より良い、差 0.02〜0.10）
- **halfconst 1.5e-3（linear・cosine の平均の学習率）: 2.696 / 2.655 / 2.705＝一番悪い**
- const6 6e-3: 2.525 / 2.517（種2つ）、linear6: 2.466 / 2.722（種1 は train も 2.56 に上がった）

- cool20（3e-3、最後の 20% で線形に 0）: 2.572 / 2.686 / 2.566＝const とほぼ同じ。cool20sq（1−sqrt）: 2.547 / 2.652 / 2.539（3つとも const よりわずかに良い、0.01〜0.03）
- **SWA（3e-3 の定数で学び、後半の重みを一様に平均した写し）: 2.470 / 2.507 / 2.476＝3つとも const より 0.09〜0.17 良く、全部の腕で一番**。学ぶ側（live）は const と全桁同じ（決定性の確かめ）。種 3〜6 を足すと SWA−const は −0.119／−0.112／−0.176／−0.166＝**7 つとも負、平均 −0.132**

読み: この設定では「平均を下げる」は悪くなる（halfconst）。効くのは「最後に揺れを抑える」こと。いちばん効いたのは学習を変えずに後半の重みを平均するだけの SWA で、cosine（0.02〜0.10）や cooldown より大きい（論文では SWA は cooldown に少し届かない。ここでは逆。16 周・小さな corpus の話かもしれない）。brain-merge の 0.02 の結果とは別の効き方。held は同じ fixture の後ろ 1/4。

## 終わりの無い形（2026-10-11、`swaw P`・`ema H [K]`、種 0〜4、16 周＝1536 歩）
- swaw 97（保存ごとに和を捨てる窓）・swaw 388・ema 100（半減 100 歩）。**後半（768 歩より後）の保存点で写し−live: ema 40/40、swaw97 40/40、swaw388 10/10 が負**（平均 −0.130／−0.085／−0.076、最も小さい差 −0.031／−0.044／−0.027）。前半は live が速く下がるので写しが負けることがある（全体では ema 10〜11/15、swaw97 12〜14/15）
- 恒等のコントロール: swaw 1（平均＝live）は 96 回とも差 0。live の最終値はどの腕でも種ごとに全桁同じ（測ることが学習を乱さない）
- ema の K（K 歩に1回だけ畳む。常駐の DMN は1回の呼び出しで 8 歩）は別に測る

## p-kernel のどこに入れるか（設計、2026-10-11）
live は今のまま（定数の学習率・同じ更新の列）。student_shell.c に重み1つ分の float の写し（S の赤子で約 7.6MB、取れなければ写し無しで今と同じ）を持ち、DMN の呼び出しごとに ema で畳む。**保存するのは live と写しのうち held が低い方**（今より悪いものは保存しない。選ぶ候補は2つだけ）。保存の判定（g_dmn_saved_loss）もその held で。再起動後は保存した重みから live が再開する（Adam のモーメントは live のもの）。既定は環境変数で入れる形から始め、常駐の cert で写しが勝つことを示してから既定にする。壊れうる試験は調べて無し（再起動後の一致を見る cert は無い。student_yield_test の memcmp は live だけ）。

## どう測れば効いたと言えるか
同じ歩数・窓・順で、SWA の写しの held が const より種 5 つ以上の対で一貫して低いこと（7/7 で満たした）。陰性コントロール: halfconst（効かない＝満たした）と前半の窓の SWA（swa1）: 2.701 / 2.634 / 2.716＝種 0・2 は const より悪いが、**種 1 は 0.04 良い**（const が一番過学習した種）。きれいな 3/3 ではない。
