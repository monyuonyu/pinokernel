# 学習率の計画（研究メモ、ROADMAP 研究・inbox #21-3c の副産物）

2026-10-08。出典（本文で確認）: Hägele, Bakouch, Kosson, Ben Allal, Von Werra, Jaggi, "Scaling Laws and Compute-Optimal Training Beyond Fixed Training Durations"（arXiv 2405.18392）。定数の学習率で学び、最後の 20% だけ 0 へ下げる（cooldown。式(1)、形は線形か 1−sqrt）と cosine と同じくらい良い。終わりの歩数を前もって決めなくてよい。定数の間の重みを平均する（SWA）だけでも、cooldown との差はかなり縮まる（§4.1）。

## 何が効くのか
brain-merge.md の副産物（Adam 0.02、675B で const 2.19 → linear 1.43）は「学習率を下げたから」か「下げ方の形」かが分からなかった。常駐の赤子は 3e-3 の定数で、終わりが無い（DMN が 2 周ずつ回り続ける）ので、cosine のような「全体の長さ」を前提にした計画はそのままでは入らない。

## 測った（probe、`tests/llm/lr_sched_probe.c`、R=16 周、TEACHER_FIXTURE 4155B・seqlen 32・後ろ 1/4 が held、種3つ。cert ではない）
held の最後（種 0/1/2）:
- const 3e-3（今）: 2.560 / 2.675 / 2.568
- linear 3e-3→0: 2.519 / 2.630 / 2.571
- cosine: 2.497 / 2.577 / 2.548（3つとも const より良い、差 0.02〜0.10）
- **halfconst 1.5e-3（linear・cosine の平均の学習率）: 2.696 / 2.655 / 2.705＝一番悪い**
- const6 6e-3: 2.525 / 2.517（種2つ）、linear6: 2.466 / 2.722（種1 は train も 2.56 に上がった）

- cool20（3e-3、最後の 20% で線形に 0）: 2.572 / 2.686 / 2.566＝const とほぼ同じ。cool20sq（1−sqrt）: 2.547 / 2.652 / 2.539（3つとも const よりわずかに良い、0.01〜0.03）
- **SWA（3e-3 の定数で学び、後半の重みを一様に平均した写し）: 2.470 / 2.507 / 2.476＝3つとも const より 0.09〜0.17 良く、全部の腕で一番**。学ぶ側（live）は const と全桁同じ（決定性の確かめ）

読み: この設定では「平均を下げる」は悪くなる（halfconst）。効くのは「最後に揺れを抑える」こと。いちばん効いたのは学習を変えずに後半の重みを平均するだけの SWA で、cosine（0.02〜0.10）や cooldown より大きい（論文では SWA は cooldown に少し届かない。ここでは逆。16 周・小さな corpus の話かもしれない）。brain-merge の 0.02 の結果とは別の効き方。種ごとの揺れも約 0.1 あるので、種を増やして確かめる。held は同じ fixture の後ろ 1/4。

## p-kernel のどこに入れるか（案、まだ作らない）
学んでいる重み（live）は定数のまま回し続け、**保存する写し（persist の時）だけ**を SWA で作る（第一候補。重み1つ分の和の置き場が要る＝S の赤子で n_params×4〜8 バイト）。live の流れも、決定性（同じ更新の列）も変わらない。平均の窓は「最後に保存してから」など終わりの無い形にする（後半、は終わりを知っている形）。

## どう測れば効いたと言えるか
同じ歩数・同じ窓・同じ順で、cooldown／SWA の写しの held が const より、種 5 つ以上の対で一貫して低いこと。陰性コントロール: halfconst（平均だけ下げる）と、平均の窓を最初の半分にした SWA（古い重みを混ぜるだけ）は効かないはず。
