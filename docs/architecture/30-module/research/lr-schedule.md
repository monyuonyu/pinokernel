# 学習率の計画（研究メモ、ROADMAP 研究・inbox #21-3c の副産物）

2026-10-08。出典（本文で確認）: Hägele ほか "Scaling Laws and Compute-Optimal Training Beyond Fixed Training Durations"（arXiv 2405.18392）。定数の学習率＋最後の 20% の cooldown（式(1)）は cosine と同じくらい良く、終わりの歩数を前もって決めなくてよい。定数の間の重みの平均（SWA）でも差はかなり縮まる（§4.1）。

## 何が効くのか
brain-merge.md の副産物（const 2.19 → linear 1.43）が「下げたから」か「形」かを分ける。常駐の赤子は 3e-3 の定数で終わりが無いので、全体の長さを前提にした計画は入らない。

## 測った（probe `tests/llm/lr_sched_probe.c`、16 周、TEACHER_FIXTURE・seqlen 32・後ろ 1/4 が held。cert ではない）
held の最後（種 0/1/2）: const 2.560/2.675/2.568、linear 2.519/2.630/2.571、cosine 2.497/2.577/2.548、**halfconst（平均の学習率）2.696/2.655/2.705＝一番悪い**、cool20 は const とほぼ同じ、cool20sq は 0.01〜0.03 良い。
**SWA（後半の重みの一様平均）: 2.470/2.507/2.476、種 7 つとも const より良い（平均 −0.132）**。live は const と全桁同じ。
読み: 平均を下げると悪くなる。効くのは最後に揺れを抑えること。いちばん効くのは学習を変えずに平均するだけ（論文とは逆に cooldown より大きい。小さな corpus の話かもしれない）。

## 終わりの無い形（2026-10-11、`swaw P`・`ema H [K]`、種 0〜4、1536 歩）
- swaw（保存ごとに和を捨てる窓）97・388 歩、ema（半減 100 歩）。**後半（768 歩より後）の保存点で写し−live は ema 40/40、swaw97 40/40、swaw388 10/10 が負**（平均 −0.130/−0.085/−0.076、最小の差 −0.031/−0.044/−0.027）。前半は live が速く下がり写しが負けることがある
- ema を 8 歩に1回だけ畳む形（常駐の呼び出し1回分、K=8）も後半 40/40 が負、平均 −0.130（K=1 と同じ）
- 恒等のコントロール swaw 1 は 96 回とも差 0。live の最終値は腕によらず全桁同じ
- 陰性コントロール（10-08）: halfconst は効かない。前半の窓の SWA は種 0・2 で const より悪いが種 1 は 0.04 良い（きれいな 3/3 ではない）

## p-kernel のどこに入れるか（設計、2026-10-11）
live は今のまま。student_shell.c に重み1つ分の float の写し（約 7.6MB、取れなければ今と同じ）を持ち、DMN の呼び出しごと（8 歩）に ema で畳む。**保存するのは live と写しのうち held が低い方**（今より悪いものは保存しない）。保存の判定もその held で。再起動後は保存した重みから live が再開する。最初は環境変数で入れ、常駐の cert で写しが勝つと示してから既定に。再起動後の一致を見る cert は無い（調べた）。

## どう測れば効いたと言えるか
同じ歩数・順で、写しの held が live より種 5 つ以上で一貫して低い（満たした）。常駐の cert では、写しを使わない腕（環境変数なし）と保存された held を同時に比べる。
