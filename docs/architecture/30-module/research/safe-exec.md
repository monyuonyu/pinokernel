# 検査してから動かす小さな実行環境（研究メモ、AI OS の候補 (1)）

2026-10-22。出典（本文を読んだ）: Zheng ほか "Towards Agentic OS: An LLM Agent Framework for Linux Schedulers"（SchedCP、arXiv 2509.01245v4）§2・§3・§5。Linux の `kernel/bpf/verifier.c`（master、10-22 取得）の頭の説明と反復子の説明、`Documentation/bpf/verifier.rst`。NVD の CVE-2021-3490・CVE-2022-23222。AIOS（arXiv 2403.16971）は題と実在だけ確かめた（本文は未読、この題材には使わない）。

## 何が効くのか（仕組み）
- eBPF: 読み込む前に検査器が全部の道をなぞり、レジスタの型と値の幅を追って、範囲外の読み書き・初期化していないレジスタ・届かない命令を拒む。大きさは 4096 命令（BPF_MAXINSNS）、なぞる量は 100 万命令（BPF_COMPLEXITY_LIMIT_INSNS）で打ち切る。**止まることは検査器だけでは決まらない**: 反復子は「いつか NULL を返し、その後も NULL」という核の側の約束に頼る（verifier.c の process_iter_next_call の説明）。頭の説明は「ループは拒む」のままで、今のコードとずれている＝説明も確かめる対象
- 検査器そのものが穴になる: CVE-2021-3490（32bit の幅の追い方の誤り→範囲外の読み書き）、CVE-2022-23222（*_OR_NULL のポインタ算術）。**検査器が正しいことは前提にできない**
- SchedCP: 生成した eBPF を (1) 核の検査器 (2) 飢えなど論理の静的検査 (3) 小さな VM で動かす試験、の順に通し、通ったものに署名つきの許可を出して、少しずつ出し、悪くなれば戻す。ただし §5 は「予備的な評価」で、**検査が悪いものを拒んだ数は出ていない**（壊したら赤の証拠が無い）

## p-kernel のどこに入れるか
今の selfc（`arch/linux/selfc.c`）は TCC で生の機械語にし、fork した子で RLIMIT（CPU 30 秒・64MB）だけで守る。Linux 版だけで、ファイルの頭に「検査器は無い」とある。署名・内容の一致・試しの期間での戻しはある（2-8 の一部）。
案: `arch/common/` に小さな命令の形（固定長、レジスタ 8 本、決まった大きさの作業場だけ読み書き、前向きの飛び先と回数が定数のループだけ）と、その**検査器**と**解釈器**を置く。機械語にしない＝ベアの機体でも同じに動く。解釈器も境界を確かめる（検査器を信じない二重の守り）。2-2（書ける≠動かせる）・2-8（受け入れの条件）・Lean の候補（小さい命令の形なら「検査を通れば止まり、はみ出さない」が定理になる）につながる。

## どう測れば効いたと言えるか（第1段の事前の形、2026-10-22 03:20、コードの前）
命令の形: 8 バイト（op・dst・src・imm）、レジスタ r0〜r7（32bit、初期化していないものは読めない）、作業場 64 バイト、命令 256 個まで。飛び先は前向きだけ。`LOOP n,len` は後ろの len 個を n 回（n ≤ 1024、入れ子なし）。検査器はレジスタの値の幅をなぞり、ループの体で書くレジスタは入口で幅を全部に広げる。歩数の上限＝ループの外の命令の数＋Σ n×len。
- V1 でたらめな命令列（通りやすいように寄せて作る）を 20 万本、種 3 つ: 検査を通ったものは、解釈器の確かめ（作業場の外・歩数の上限超え・知らない命令）に**一度も引っかからない**。通る割合は 10% 以上（空回りの試験にしない）
- 壊したら赤（検査器の壊し方、コードの前に固定）: B1 作業場の端を 1 つ緩める・B2 後ろ向きの飛び先を許す・B3 ループの入口で幅を広げない・B4 足し算のあふれを見ない（CVE-2021-3490 と同じ種類の誤り）。どれも同じ 20 万本で引っかかる件数 > 0 が種 3 つとも
- 予想: V1 は 0 件。B1・B2 は種 3 つとも見つかる。B3・B4 は見つかるが件数は少ない（でたらめでは狙った形が出にくい）。外れたら生成の寄せ方を直す前に、その外れをこのメモに書く
- 役に立つかの側（次の段）: 今の selfc の例の単位を書き直して、検査を通ること（拒みすぎの確認）

## 第1段の結果（2026-10-22 03:17、c348a961 の木、`tests/host/run_sxvm.sh 200000 1 2 3`、ASan+UBSan、生ログ `pk-scratch/rs-sx1/`）
- 頭: 20 万本×種 3 で通ったのは 27795/27768/27715（13.9%）、うちループあり 1514/1545/1461・作業場の読み書きあり 4097/3992/4089。**解釈器の確かめに引っかかったのは 0 件**（3 種とも）。手書きの K 8 件（通るもの 2・拒むもの 6）も全部当たり
- 壊し方（引っかかった件数、種 1/2/3）: B1 EDGE 124/128/118（全部 作業場の外）・B2 BACKJ 5233/5155/5498（歩数の上限超え 5165/5090/5427、作業場の外 53/57/60、書いていないレジスタ 15/8/11）・B3 WIDEN 67/65/84・B4 ADDOVF 15/31/31。**予想どおり 4 つとも 3 種で見つかり、B3・B4 は少ない**。K でも B1・B2・B3 は 1 件ずつ赤、B4 を見る K は無い
- 読み: 「検査を通ったものだけ動かす」形は、この小ささなら手で作れて、壊した検査器はでたらめの列で見つかる。限界: 0 件は「この生成のしかたで見つからなかった」だけで、正しさの証明ではない（B4 は 20 万本で 15 件＝狙いの形が珍しい壊し方は見落とし得る）。検査器は区間だけで、値どうしの関係（r1 < r2 など）は追わないので、役に立つプログラムを拒みすぎるかは未測定（次の段）。どこにもつないでいない（selfc もそのまま）

## 第2段の事前の形（2026-10-22 03:25、第1段の結果を見たあと・コードの前）
selfc の単位は印字・pub/sub・待ちを呼び、終わらない輪で動く。eBPF と同じく「出来事ごとに 1 回、有限の歩数で走る手続き」に替え、外に出る口は**呼び出し**（`SX_CALL`、番号で選ぶ）だけにする。
- 2a 網羅: 決まった前置き（r0=0、r1=作業場の 0 番の値、r2=0xFFFFFFF0）のあとに、小さな命令の表から長さ 1〜3 の全部の並び＋EXIT。予想: 頭は 0 件、B1〜B4 は 4 つとも見つかる（B4 は ANDI・負の ADDI・LDB の 3 つで届く）
- 2b 呼び出し: 1 番＝pub（作業場の [r1, r1+r2) を送る）、2 番＝log（r1 の値）。検査器は pub の前に r1・r2 が書かれていて、r1+r2 ≤ 64 が値の幅で言えることを確かめる。呼び出しのあと r1〜r5 は書いていない扱い（eBPF と同じ）、r0 は呼び出しの答え。呼び出す側も境界を確かめる（二重）。壊し方 B5: pub の検査で長さを見ない。予想: 頭は第1段の V1 と 2a で 0 件、B5 は V1 で種 3 つとも見つかる
- 2c 役に立つか: selfc の demo の checksum（v = v×31 + c、文字列は作業場）と、gate v1 の「A:1 を出す」を、出来事 1 回分の手続きとして書く。予想: どちらも検査を通り、答え（checksum の値・pub の中身）が C で計算したものと一致
